### **1. Общие положения**

**Название проекта**: MemorizeBot  
**Цель**: Разработать асинхронного Telegram-бота, способного принимать от пользователя фото и файлы, сохранять их на локальном диске с метаданными, обеспечивать поиск по наименованию файлов и экспортировать полный архив воспоминаний в виде **самодостаточного ZIP-архива**, содержащего HTML-альбом и все связанные файлы.  
**Платформа**: Telegram API (aiogram 3.x), Python 3.10+, SQLite (или PostgreSQL), Linux/Windows/macOS.  
**Срок выполнения**: 14 календарных дней.  
**Критерий успешности**: Бот корректно выполняет все функции, описанные в разделе 3, без внешних зависимостей, кроме указанных в разделе 5.  
**Ключевое требование**: **HTML-файл не может быть отправлен отдельно**. Экспорт возможен **только через ZIP-архив**, содержащий HTML и все файлы воспоминаний в корректной структуре папок.

### **2. Ограничения и требования к реализации**

| Категория | Требование |
|----------|-----------|
| **Функциональные ограничения** | Бот **не обрабатывает** текстовые сообщения, голосовые, видео, стикеры, опросы или любые другие типы сообщений, кроме `photo` и `document`. Все иные входы игнорируются. |
| **Архитектура** | Проект должен быть структурирован по модулям (см. раздел 4). Нельзя использовать монолитный `main.py`. |
| **Безопасность** | Токен бота **не должен** храниться в коде. Использовать `.env` + `python-dotenv`. |
| **Хранение данных** | Все файлы сохраняются **локально** в папке `memories/`. Никаких облачных хранилищ, ссылок, CDN. |
| **База данных** | Использовать **SQLAlchemy 2.0+ ORM** с SQLite. Никаких raw SQL-запросов без необходимости. |
| **Экспорт** | Команда `/export` **обязательно** должна генерировать **ZIP-архив**, содержащий:  
  - HTML-файл (`memories_{user_id}.html`) в корне архива,  
  - папку `memories/` со всеми оригинальными файлами воспоминаний.  
  **Отправка отдельного HTML-файла без ZIP — считается ошибкой.** |
| **Логирование** | Все действия пользователя и системные события логируются в файл `bot.log` в формате ISO 8601. |
| **Масштабируемость** | Код должен быть организован так, чтобы добавление нового типа файла (например, `video`) не требовало переписывания основной логики. |
| **Работа вручную** | Бот **не запускается в фоне**, не использует `APScheduler`, не отправляет уведомления по расписанию. Работает только на команды пользователя. |

### **3. Функциональные требования**

#### **3.1. Приём и сохранение файлов**
- Бот должен принимать:
  - `Photo` (любое изображение, отправленное как фото)
  - `Document` (любой файл, отправленный как документ — PDF, TXT, ZIP, DOCX и т.д.)
- Для каждого файла:
  - Создать уникальное имя в формате:  
    `memories/{type}_{id}_{original_name}`  
    где:
    - `type` — `"photo"` или `"file"`
    - `id` — первичный ключ из БД
    - `original_name` — исходное имя файла (без пробелов и специальных символов, заменить на `_`)
  - Сохранить файл в директорию `memories/` (создавать её при необходимости)
  - Записать в БД запись с полями:
    | Поле | Тип | Описание |
    |------|-----|----------|
    | `id` | Integer | PRIMARY KEY, AUTOINCREMENT |
    | `user_id` | Integer | Telegram ID отправителя |
    | `type` | String | `"photo"` или `"file"` |
    | `file_path` | String | Относительный путь к файлу (например, `memories/photo_42_IMG_123.jpg`) |
    | `original_name` | String | Исходное имя файла (с сохранением расширения) |
    | `file_size` | Integer | Размер файла в байтах |
    | `created_at` | DateTime | Время получения в UTC |
    | `tags` | JSON | Пустой массив `[]` (зарезервировано для будущего) |

> **Примечание**: Имя файла должно быть очищено от опасных символов (`/`, `\`, `:`, `*`, `?`, `"`, `<`, `>`, `|`) — заменить на `_`.

#### **3.2. Поиск по файлам**
- Команда: `/search <query>`
- Бот выполняет поиск по полю `original_name` в базе данных с **регистронезависимым** совпадением подстроки.
- Возвращает список найденных записей в формате:
  ```
  🔍 Найдено {count} воспоминаний:
  1. 📷 photo_42_IMG_123.jpg — 2.1 MB — 2025-04-05
  2. 📄 file_88_report.pdf — 512 KB — 2025-04-03
  ```
- Каждая запись — **Inline-кнопка** с текстом `Показать` и `callback_data` в формате: `show:{id}`
- При нажатии кнопки бот отправляет **оригинальный файл** обратно пользователю через `await message.answer_document()` или `await message.answer_photo()`.

#### **3.3. Экспорт в ZIP-архив (обязательно!)**
- Команда: `/export`
- Бот:
  - Собирает **все записи** текущего пользователя (`user_id`)
  - Генерирует **HTML-файл** с именем: `memories_{user_id}.html`  
    **Структура HTML**:
    ```html
    <!DOCTYPE html>
    <html lang="ru">
    <head>
        <meta charset="UTF-8">
        <title>Мои воспоминания</title>
        <style>
            body { font-family: Arial, sans-serif; margin: 20px; }
            .memory { margin: 20px 0; padding: 15px; border: 1px solid #eee; border-radius: 8px; }
            .memory img { max-width: 300px; height: auto; }
            .memory a { color: #0066cc; text-decoration: none; }
        </style>
    </head>
    <body>
        <h1>Мои воспоминания</h1>
        <!-- Каждая запись -->
        <div class="memory">
            <img src="memories/photo_42_IMG_123.jpg" alt="Фото">
            <p><strong>Тип:</strong> фото</p>
            <p><strong>Имя:</strong> IMG_123.jpg</p>
            <p><strong>Размер:</strong> 2.1 MB</p>
            <p><strong>Дата:</strong> 2025-04-05</p>
        </div>
        <div class="memory">
            <a href="memories/file_88_report.pdf">📄 report.pdf</a>
            <p><strong>Тип:</strong> файл</p>
            <p><strong>Размер:</strong> 512 KB</p>
            <p><strong>Дата:</strong> 2025-04-03</p>
        </div>
    </body>
    </html>
    ```
  - Создаёт **ZIP-архив** с именем: `memories_archive_{user_id}.zip`
    - В корне архива: `memories_{user_id}.html`
    - Внутри архива: папка `memories/`, содержащая **все файлы воспоминаний** (фото и документы) в исходном виде
  - Отправляет **только ZIP-архив** пользователю как документ через `await message.answer_document(InputFile(zip_path))`
  - После отправки — **удаляет ZIP-файл** с диска

> ✅ **Критическое требование**:  
> После распаковки архива и открытия `memories_{user_id}.html` в браузере — **все изображения и файлы должны отображаться корректно**.  
> **Если HTML открывается, но картинки не грузятся — проект не сдан.**

#### **3.4. Логирование**
- Все действия записываются в файл `bot.log` в формате:
  ```
  [YYYY-MM-DD HH:MM:SS] USER {user_id}: {action}
  ```
  Примеры:
  ```
  [2025-04-05 10:30:22] USER 12345: uploaded photo "IMG_123.jpg" (size: 2100000 bytes)
  [2025-04-05 10:31:05] USER 12345: searched for "IMG" → found 1 result
  [2025-04-05 10:32:10] USER 12345: exported ZIP archive (5 files)
  [2025-04-05 10:35:01] USER 12345: sent file "report.pdf"
  [2025-04-05 10:35:02] USER 12345: ignored text message: "Привет"
  ```

#### **3.5. Дополнительные команды**
- `/start` — приветствие:  
  > “Привет! Отправляй мне фото или файлы — я сохраню их как твои воспоминания. Используй /search для поиска и /export для экспорта всего архива.”
- `/help` — краткая инструкция:  
  > “Отправь фото или файл. Используй /search <слово> для поиска по имени файла. /export — экспортировать полный архив в ZIP.”

### **4. Архитектурные требования**

Проект должен быть разбит на следующие модули (примерно, можно реализовать по-своему):

```
memorizebot/
├── main.py                  # точка входа: инициализация бота и диспетчера
├── config.py                # загрузка токена из .env, пути к папкам
├── models/
│   └── memory.py            # SQLAlchemy модель Memory (с метаданными)
├── handlers/
│   ├── photo.py             # обработчик фото (Message.photo)
│   ├── file.py              # обработчик файлов (Message.document)
│   └── commands.py          # /start, /help, /search, /export
├── utils/
│   ├── file_saver.py        # функция save_file(file_id, original_name, type) → file_path
│   ├── html_exporter.py     # функция generate_html(user_id, memories) → html_content
│   ├── zip_archiver.py      # функция create_zip_archive(user_id, memories) → zip_path
│   └── logger.py            # функция log_action(user_id, action)
├── memories/                # папка для хранения файлов (создаётся автоматически)
└── .env                     # BOT_TOKEN=123456:ABC-DEF1234ghIkl-zyx57W2v1u123ew11
```

> **Требование**: Каждый модуль должен иметь **одну ответственность**.  
> **Запрещено**: Использовать глобальные переменные для хранения состояния бота.  
> **Рекомендовано**: Использовать `async with session.begin()` для всех операций с БД.  
> **Обязательно**: В `zip_archiver.py` использовать `zipfile.ZipFile` с `arcname` для сохранения структуры `memories/`.

| Категория | Требования |
|----------|------------|
| **Язык** | Python 3.10+ |

| **Логирование** | стандартный модуль `logging` |

| **Зависимости** | Только `aiogram`, `sqlalchemy`, `python-dotenv`, `python-multipart` (если нужно) |

> **Запрещено**: Использование сторонних NLP-библиотек, OCR, транскрипции, машинного обучения, внешних API, `shutil`, `tarfile`, `subprocess`.

### **8. Примечания**

- Проект **не требует** развертывания на сервере.  
- Бот работает **только в локальной среде**.  
- Никакие данные не передаются за пределы устройства.  
- Цель — не создать «умного» бота, а **научиться писать структурированный, масштабируемый и документированный код**, используя **самостоятельный поиск решений**.

> **Предупреждение**:  
> Ни один из методов или решений, описанных в этом ТЗ, **не будет предоставлен в готовом виде**.  
> Все компоненты — от сохранения файла до генерации ZIP-архива — требуют **самостоятельного исследования и реализации**.  
> Использование чужого кода без понимания — равносильно несдаче.

3. Убедитесь, что:
   - Все картинки отображаются
   - Все PDF/файлы имеют рабочие ссылки
   - Нет ошибок 404 в консоли браузера
